# رفيق — رفيقك الرياضي

تطبيق عربي RTL للموبايل، مع تطبيق مرافق لـGalaxy Watch 6 ومعاينة متجاوبة للكمبيوتر. React / TypeScript / Capacitor، Android وWear OS، وGoogle Gemini API.

## تشغيل الكمبيوتر

```powershell
npm install
npm run dev
```

المعاينة: `http://localhost:5173`. لحوار Gemini بالمعاينة، انسخ `.env.example` إلى `.env.local`، أضف `GEMINI_API_KEY` ثم شغّل `npm run api`. اختر النموذج من «الإعدادات ← إعداد Gemini API ← فحص الاتصال وجلب النماذج». المفتاح لا يدخل ملفات الواجهة أو المستودع. عند تعديل البيئة أعد تشغيل خادم API.

## تشغيل الموبايل

1. ثبّت APK الموبايل على S26 Ultra.
2. افتح إعداد Gemini API. اترك عنوان الخادم فارغاً للاتصال المباشر.
3. أدخل مفتاح Google API في حقل خزنة الجهاز واضغط حفظ المفتاح. يُشفّر بـAES-GCM بمفتاح من Android Keystore. لا يدخل النسخ الاحتياطية أو سجل التعديلات ولا تُعاد قراءته إلى JavaScript.
4. افحص الاتصال، اختر نموذجاً متاحاً لحسابك، فعّل موافقة مشاركة السجل واحفظ. تكلفة Google وصلاحيات النماذج حسب حسابك.
5. استورد ملف التسليم Markdown من إعدادات الذاكرة. في معاينة الكمبيوتر يوجد زر لتحميل النسخة المحلية الخاصة من `server/private/ashraf.md` إن وجدت. هذا الملف مستثنى من Git ولا يدخل APK.
6. فعّل المزامنة من Samsung Health إلى Health Connect. افتح «صحتي والساعة»، امنح الصلاحيات التي تختارها، ثم حدّث البيانات.

## تشغيل الساعة

ثبّت APK الساعة عبر أدوات المطور/ADB اللاسلكي على Watch 6، وAPK الموبايل من نفس البناء. كلاهما بالحزمة `app.rafiq.personal` ونفس توقيع debug؛ Wear Data Layer يشترط تطابق الحزمة والتوقيع.

الساعة تعرض الجلسة وتمارينها، وتسجّل الأوزان والتكرارات والماي، مع مؤقت راحة واهتزاز. الأحداث Data Items بمعرفات فريدة، تُزامن عند الاتصال. الموبايل يستوردها بدون تكرار ويؤكدها بعد الحفظ المحلي الناجح. النبض والنوم والخطوات تُقرأ عبر Samsung Health وHealth Connect.

- صور محلية مؤرخة بوزن ووقفة، مقارنة صورتين، وتجهيز تحليل Gemini ثم الإرسال الصريح من المحادثة.
- محادثة Gemini محفوظة وتفريغ صوتي من الجهاز/المتصفح مع مراجعة النص والصور المرفقة. اقتراحات تسجيل الوجبة/الماء/الجولة/الكارديو/الوزن/النوم/الملاحظة تُراجع في نموذج قبل اعتمادها.
- ذاكرة شخصية قابلة للاستيراد والتعديل. المحادثة كاملة محفوظة محلياً؛ طلب AI يرسل آخر 40 رسالة وأحدث سجلات المتابعة وملف الذاكرة، وليس التاريخ كله بكل طلب.
- IndexedDB مع ترحيل النسخة الأولى من Preferences، سجل تعديلات تفصيلي يستثني الصور ورموز الاتصال، ومعالجة فشل الحفظ.
- نسخ احتياطي AES-GCM بكلمة مرور وPBKDF2، واستعادة بعد التحقق من المخطط. رموز الاتصال ومفتاح Google مستثنيان.
- طباعة/حفظ PDF للكورس من المتصفح أو طباعة أندرويد الأصلية.
- الخط العربي مضمّن؛ الواجهة والسجلات تعمل محلياً بدون تحميل خط خارجي.

## حدود التحقق

تم اختبار Gemini فعلياً بنموذج gemini-3.8-flash، بما فيه دورة اقتراح تسجيل ماء ثم مراجعته وحفظه ببيانات اصطناعية فقط. بقية اختبارات المحادثة تستخدم استجابات محاكاة حتى لا تستهلك API عند كل تشغيل. يلزم اختبار Health Connect والصوت وخزنة المفتاح والطباعة ومزامنة الساعة على الجهازين الفعليين. الحقول تختلف حسب بيانات Samsung Health والصلاحيات؛ ليس كل حساس سامسونج متاحاً. النوم المعروض آخر جلسة متاحة، وليس مجموع كل الجلسات والمراحل.

السجلات والصور محمية بعزل التطبيق في النظام، وليست قاعدة IndexedDB مشفرة بالكامل. النسخ الاحتياطية مشفرة. قد تبقى نصوص قديمة في سجل التدقيق بعد حذف سجل فردي؛ مسح البيانات الكامل يحذف سجل التدقيق. لا يحتوي المستودع على ملفات المستخدم الشخصية. لا يُعرض عمر بيولوجي أو حرق أو نسبة دهون مصطنعة باعتبارها قياساً دقيقاً.

## النشر السحابي

الرفع إلى GitHub لا ينشر الخدمة تلقائياً. هذه النسخة تتضمن تكامل Supabase، لكنه يحتاج إعداداً واختباراً فعلياً قبل الاعتماد عليه.

1. نفّذ `supabase/migrations/202610180001_rafiq_cloud.sql` في SQL Editor للمشروع. يتضمن عزل المستخدمين RLS ومخزناً خاصاً للصور ومزامنة بإصدارات وكشف التعارضات.
2. من Supabase CLI بعد تسجيل دخول حساب الإدارة: `supabase link --project-ref YOUR_PROJECT_REF` ثم `supabase functions deploy rafiq-ai`. الدالة تتحقق من جلسة المستخدم بواسطة `auth.getUser` لكل طلب. أضف `GEMINI_API_KEY` و`GEMINI_MODEL` إلى Edge Function Secrets من لوحة Supabase. لا تستخدم مفاتيح الإدارة في الواجهة.
3. اربط المستودع في Vercel. أمر البناء `npm run build` والمجلد `dist`. أضف متغيرات البناء `VITE_CLOUD_ENABLED=true` و`VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY`، ثم أعد النشر.
4. أضف رابط Vercel إلى Site URL وRedirect URLs في Supabase Auth. فعّل تأكيد البريد واضبط SMTP للإنتاج. بعد استعادة كلمة المرور افتح إعدادات الحساب لتغييرها.
5. اختبر إنشاء حسابين وعزل السجلات والصور، تعديل السجل من جهازين، انقطاع الشبكة، التعارضات، واستدعاء Gemini. اختبارات الواجهة المحلية لا تثبت عمل الخدمات المنشورة. اضبط حصص Google والميزانية؛ لم تُضف حصة يومية لكل مستخدم في هذه النسخة.
6. لبناء Android بالنمط السحابي، ضع متغيرات VITE أعلاه في بيئة البناء ثم شغّل `npm run android:sync`. النسخ القديمة من APK لا تتحدث تلقائياً.

سجل كل حساب مخزّن مؤقتاً على الجهاز لاستعماله عند الانقطاع. تسجيل الخروج لا يمسح هذا التخزين، لذلك استخدم جهازاً شخصياً. الحذف الفردي قد يبقي النص السابق في سجل التدقيق. لا توجد واجهة لمسح الحساب السحابي بالكامل في هذه النسخة.

## إصدارات الهاتف والساعة

نسخ الإنتاج تستخدم مشروع Supabase المرفق افتراضياً؛ `src/cloud-public.json` يحتوي عنوان المشروع ومفتاح publishable العام فقط. مفاتيح Google والإدارة لا تدخل ملفات الواجهة أو APK. يمكن تجاوز الإعدادات بمتغيرات VITE. للتطوير المحلي يبقى النمط المحلي افتراضياً؛ `VITE_CLOUD_ENABLED=true` يفعّل الحسابات أثناء التطوير أيضاً.

الإصدار الحالي في `src/version.json` ويُقرأ في Gradle للتطبيقين. عند إصدار تحديث:

1. شغّل `powershell -ExecutionPolicy Bypass -File scripts/bump-version.ps1 -Version 1.1.1` مع رقم جديد أكبر من السابق، ثم افحص التغييرات وشغّل الاختبارات.
2. ابنِ بواسطة `scripts/build-android.ps1` على جهاز يحافظ على نفس مفتاح التوقيع. هذه إصدارات شخصية بتوقيع debug؛ حافظ على خزنة Android المحلية ولا تنشرها.
3. ارفع تغييرات الكود ثم أنشئ GitHub Release عادي بعنوان `v1.1.1`، وأرفق الملفين بالاسمين الثابتين `Rafiq-phone.apk` و`Rafiq-watch.apk`. لا تجعل الإصدار latest قبل اكتمال رفع الملفين.
4. زر الهاتف في الإعدادات يفحص آخر Release ويقارن رقم الإصدار، ويفتح تنزيل APK من المستودع المحدد. التثبيت يحتاج موافقة المستخدم وأحياناً السماح للمتصفح بتثبيت التطبيقات. لا تحذف النسخة السابقة.
5. منذ 1.5.0 زر الساعة يفحص الإصدار وينزّل APK عبر الإنترنت، ويتحقق من الحزمة والتوقيع والإصدار ثم يطلب تثبيت النظام. يلزم السماح لرفيق بتثبيت تحديثه أول مرة إذا أتاح نظام الساعة ذلك؛ لا يوجد تثبيت صامت. النسخ الأقدم تحتاج أول تحديث عبر ADB. ثبّت الساعة بـ`adb -s WATCH_ADDRESS install -r Rafiq-watch.apk` عبر اتصال ADB اللاسلكي بعد الاقتران. يمكن تثبيت الهاتف بـ`adb -s PHONE_SERIAL install -r Rafiq-phone.apk` أو بفتح الملف على الهاتف.

في Supabase Authentication → URL Configuration اضبط Site URL على `https://friend-delta-blue.vercel.app` وأضف `https://friend-delta-blue.vercel.app/**` إلى Redirect URLs. التسجيل من APK يفتح تأكيد البريد في الموقع؛ بعد التأكيد ارجع للتطبيق وسجّل الدخول. استعادة كلمة المرور تتم بالموقع، من إعدادات الحساب بعد فتح رابط الاستعادة.

## مركز الأداء 1.2

واجهة داكنة جديدة، حلقات متحركة للجاهزية والنوم، الحمل القلبي المرصود، اتجاهات 7/14/28 يوماً، تفاصيل مراحل النوم عند توفرها، هدف نوم وموعد تهدئة تقديري، سجل يومي للطاقة وألم العضلات والإجهاد والعادات، تحليل ارتباط العادات بنوم اليوم التالي، تنفس موجه، وعرض الحجم الفعلي للتمارين والأنشطة التي شاركها Health Connect. الألوان والحركة قابلة لاحترام إعداد النظام لتقليل الحركة.

تُقرأ HRV والتنفس عبر Health Connect إذا شاركتهما الساعة وكان الإذن ممنوحاً. استيراد 14 يوماً من شاشة الصحة يبني الخط الأساسي تدريجياً ويحفظ كل يوم مكتمل. بعد أول ربط صحي، يجري التحديث عند فتح التطبيق إذا مضى 15 دقيقة، والتطبيق في الواجهة فقط. لا توجد خدمة تسجيل صحية خاصة برفيق تعمل 24/7 في الخلفية؛ التسجيل اليومي المستمر يبقى عبر Samsung Health حسب إعداداته.

Watch 6: واجهات يومي/تمرين/نبض، حلقات متحركة، تسجيل الجولات والماء ومؤقت الراحة. قياس النبض المباشر يحتاج ضغط البدء ومنح READ_HEART_RATE على Wear OS 6 أو BODY_SENSORS على الأنظمة السابقة. تُستبعد قراءات الحساس غير الموثوقة؛ تحفظ قراءة كل 10 ثوانٍ أثناء فتح القياس فقط، ويتوقف عند مغادرة التطبيق. الهاتف يستوردها عند فتحه ثم يؤكد الحفظ. لم نضف قراءة PPG أو ECG أو BIA أو درجة حرارة الجلد بواسطة Samsung Sensor SDK، ولم نشتق HRV من bpm.

الجاهزية نموذج تجريبي شفاف خاص برفيق، وليست درجة WHOOP: النوم 40%، تغير HRV عن خط أساس سابق 30%، نبض الراحة 20%، إحساسك 10%، مع إعادة موازنة الأوزان المتاحة. لا تظهر الدرجة قبل مكونين وأحد مكونات HRV/RHR له ثلاثة أيام سابقة على الأقل. لا تُستخدم أيام مستقبلية في الخط الأساسي. الحمل القلبي مجموع الدقائق المرصودة × وزن المنطقة 1–5، بعد 10 دقائق مغطاة؛ فجوة أكبر من دقيقتين لا تُحسب. المناطق مبنية على أقصى نبض تقديري حسب العمر، وليست اختباراً سريرياً. لا يوجد ادعاء بحساب التوتر الفسيولوجي أو العمر البيولوجي أو تطابق خوارزميات WHOOP.

تدخل سجلات العادات وملخصات الصحة والهدف والتقديرات إلى سياق Gemini بعد موافقة المستخدم. لا ترسل كل عينات النبض الخام في طلب المحادثة. مخطط الحالة يرحّل الملفات السابقة بالقيم الافتراضية، والمزامنة تخزن كل يوم صحي وسجل إحساس وقراءة ساعة منفصلاً. لا تحتاج Migration SQL جديدة.

## 1.3 — الأيام المرنة والصوت والوجبات المعتادة

اتجاه بصري أسود وبرتقالي وخط Cairo مضمّن محلياً. خُففت الحركة إلى انتقالات قصيرة بدون قفز أو توهج متكرر. تغيّر طابع الساعة إلى نفس الألوان.

- الوجبات المعتادة: تثبيت وجبة من السجل، اختيار أيام ظهورها، وتعطيلها أو حذفها. التكرار في يومين مختلفين يُظهر اقتراحاً تلقائياً مع الحفاظ على الكمية والتحضير والماكروز؛ الظهور لا يسجل الأكل. الإضافة تمر بنموذج المراجعة المعتاد.
- قرار التمرين: راحة تبقي الجلسة، تأجيل لتاريخ لاحق يبقي الجلسة، أو تخطي ينتقل للتالية بدون تسجيل اكتمال. يحفظ السبب ويفعّل هدف يوم الراحة. إلغاء التخطي لا يعكس ترتيب الكورس تلقائياً؛ يمكن اختيار الجلسة من شريط الكورس.
- الصوت: MediaRecorder بتشغيل وإيقاف وإيقاف مؤقت واستئناف صريحين، بدلاً من نافذة الإملاء التي تنهي الكلام عند السكوت. حد خمس دقائق وحجم أقصى؛ استماع وتنزيل محليان. موافقة مستقلة لإرسال الملف إلى Gemini لتفريغه، مراجعة النص ثم إضافته إلى مسودة المحادثة. لا يرسل رسالة أو يسجل وجبة تلقائياً. التسجيل المؤقت يزول عند إغلاق النافذة أو الانتقال من المحادثة؛ يمكن تنزيله قبل ذلك. التفريغ له تكلفة Google كأي طلب API وقد يخطئ، خاصة بالأسماء والأوزان، ولذلك يبقى قابلاً للتحرير.
- دالة rafiq-ai تدعم transcribe بعد تحقق جلسة المستخدم؛ يجب نشرها عند تحديث نسخة ما قبل 1.3. النمط المحلي والخزنة الأصلية يدعمان المسار أيضاً.
- قراءة الضغط وحرارة الجسم من Health Connect إذا توفرا ومنحت الصلاحيات، مع عرض الضغط الانقباضي والانبساطي منفصلين ومصدرهما. يمكن تسجيل قراءة جهاز يدوياً في السجل. لا نقيس ضغطاً من bpm ولا نزعم عمراً بيولوجياً حقيقياً. ميزات Samsung Health Monitor تتأثر بالدعم والمعايرة والمنطقة، ومشاركة بياناته ليست مضمونة.

لا تحتاج جداول SQL إضافية. القوالب وقرارات التدريب وثائق مستقلة ضمن المزامنة. الإصدارات السابقة تُرحّل عبر قيم افتراضية.

## 1.4 — الطعام من الساعة

تبويب أكل في Watch: وجبة جديدة أو وصف يحتاج المراجعة، اختيار وجبة معتادة أو سابقة، تعديل عدد الحصص، مراجعة القيم والغرامات والتحضير قبل تأكيد الحفظ. لا يحتاج إدخال الوجبة المعروفة فتح الهاتف وقت التسجيل. القوائم تعتمد على آخر مزامنة من الهاتف؛ تصل حتى 20 وجبة معتادة و10 سابقة بمعلومات مختصرة لتقليل حجم Wear Data Layer.

وجبات الساعة تحفظ في قائمة انتظار خاصة على الساعة قبل الإرسال وتُعاد عند فتح التطبيق أو طلب إعادة المحاولة. بعد الحفظ الدائم في IndexedDB على الهاتف يرسل الهاتف تأكيد استلام، فتُزال من قائمة انتظار الساعة. تأكيد الاستلام يعني الحفظ على الهاتف؛ حالة المزامنة في الحساب توضح وصولها للسحابة. الهاتف يحتاج فتح رفيق ومعالجة الأحداث، والسحابة تحتاج الإنترنت. معرّفات الاستلام على الهاتف تمنع إعادة استيراد حدث وصل سابقاً، حتى بعد حذف سجله.

الوصف الذي لا يتضمن قيماً غذائية كاملة يدخل pendingFoods، وليس سجل السعرات. يظهر تنبيه على الرئيسية وصندوق مراجعة في التغذية. يمكن إكماله يدوياً أو الانتقال إلى محادثة مرتبطة به مع رفيق. عند اعتماد اقتراح وجبة يرتبط بمعرّف الوصف الأصلي ويزيله من قائمة الانتظار مرة واحدة. مسودة المحادثة لا تُرسل تلقائياً.

التحديث متوافق مع السجل السابق ولا يحتاج SQL جديدة. يلزم تحديث الهاتف والساعة معاً: نسخ الهاتف الأقدم لا تفهم أحداث الطعام الجديدة. لا توجد مزامنة سحابية مستقلة للساعة أو محادثة Gemini مباشرة داخلها في هذا الإصدار؛ أوصاف الطعام الناقصة تُراجع على الهاتف. اختبار الحساسات أو المزايا السابقة لا يعني أن جميع وظائف الجهازين اجتازت اختباراً شاملاً على العتاد.


تفاصيل جلسات Health Services ودقة التلخيص وحدود الفحص: [جودة 1.5.0](docs/QUALITY_1.5.0.md). سكربت بناء أندرويد ينتج Release افتراضياً؛ استخدم -Configuration Debug للاختبار فقط. شهادة التحديث الحالية محفوظة، ولا يلزم حذف السجل أو إنشاء SQL جديدة.
